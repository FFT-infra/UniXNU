# Alioth iOS root image v15 audit

Date: 2026-10-23

Scope: compare the current upstream `ios-sweet` documentation and root-image
tooling with the root-image requirements recorded in `NOTES.md`.  This was a
read-only source audit; no image, partition, fastboot action, or device state
was touched.

Sources:

- `ios-sweet` HEAD `067c9b3d463ecfbe37520683637ea2e6af31f3a4`, which was also
  the remote `main` HEAD when checked on 2026-10-23.
- `README.md`, `NOTES.md`, `tools/mkiosroot.sh`, and
  `tools/sweet-root-tweaks.py` at that commit.
- The v15 note was committed as `2683b6a`; the current tweak tool was
  committed earlier as `4e8f1e3` and was not updated for v15.

## Findings

### P0: the only literal v15 delta is missing

`NOTES.md:8` defines image v15 as v14 plus:

- `/private/var/preferences/SystemConfiguration/preferences.plist`
- one network service named `USB Ethernet`
- interface `DeviceName = ue0`, `Type = Ethernet`
- manual IPv4 `192.168.7.2/24`, router `192.168.7.1`
- DNS `1.1.1.1`, `8.8.8.8`
- `Automatic` selected as `CurrentSet`

There is no SystemConfiguration code or path in
`tools/sweet-root-tweaks.py`, and no generation step in `tools/mkiosroot.sh`.
The README reproduction recipe therefore stops at a v14-equivalent root, not
the v15 image documented on the phone.  This will not by itself prove that USB
internet works: `NOTES.md:10` also identifies a possible missing
`IONetworkInterface` / configd attachment.  The image-side v15 requirement is
nevertheless absent.

### P1: `mkiosroot.sh` uses a journaled loop-mount workflow that does not work
in the current Linux build environment

`tools/mkiosroot.sh:74-78` creates a journaled (`mkfs.hfsplus -J`) HFSX volume
and immediately loop-mounts it read-write.  The README documents the same
workflow (`README.md:81-85`).  The verified libguestfs result is the opposite:
the Linux HFS+ implementation can populate a non-journaled HFSX through
guestmount, while a journaled volume is read-only.

The working sequence must be separated:

1. create a non-journaled HFSX image;
2. populate it through guestmount;
3. unmount it and run HFS checks;
4. enable the journal with macOS `diskutil enableJournal`;
5. produce the sparse Android image.

This is not a v15 content item, but the committed builder and README cannot
currently reproduce the required root image in the guestmount-only environment.

### P1: the APFS compressed-file assumption is not true for the available
apfs-fuse

`tools/mkiosroot.sh:7-8` says APFS LZBITMAP files are read through
`apfs-fuse`, which "decompresses" them.  A real 20H392 file with
`com.apple.decmpfs` type 9 was tested:

- strict apfs-fuse: opening/reading the file fails with `Input/output error`;
- apfs-fuse `-l`: the read succeeds but returns zero bytes, even though stat
  reports the original non-zero size.

Using `-l` is therefore lossy and can silently turn compressed files into
empty files.  Not using `-l` makes rsync abort.  The builder needs a verified
LZBITMAP extraction path or native macOS APFS reads; neither is implemented in
the committed `mkiosroot.sh`.  A post-copy size/content manifest is also
required so this failure cannot be reported as a successful build.

### P1: activation can silently disappear while the build exits successfully

`tools/sweet-root-tweaks.py:93-107` locates the mobileactivationd system
container and writes its data ark.  If the container is not found, the function
prints a warning and returns normally (`:95-97`).  The main function does not
treat this as an error.

That means a source-layout change, incomplete rsync, or missing container
metadata can produce an image without the v14 activation state while the
builder still reports success.  This should be fail-closed, or require an
explicit `--allow-missing-activation` option.

The root image is also only one half of activation: the actual Activated state
depends on the ADT `/chosen` security properties generated by
`tools/mkadt.py` (`NOTES.md:22`).  The root-image report should record this
cross-artifact dependency.

## Requirements already covered

The following v13/v14 image mutations are present in the committed tweak tool:

| Area | Documentation | Implementation | Result |
| --- | --- | --- | --- |
| launchd | Remove `com.apple.CommCenter`; avoid daemon-crash system panics | `tools/sweet-root-tweaks.py:57-71` renames `_PanicOnCrash` and removes the CommCenter job | Covered |
| containers | Create `Bundle`, `Data/System`, `Shared/SystemGroup`, and `Temp` | `tools/sweet-root-tweaks.py:74-82` creates the paths with the recorded owners/modes | Covered when absent |

| audio | Move `VirtualAudio.plugin` to `HAL.disabled` | `tools/sweet-root-tweaks.py:110-116` | Covered when the plugin exists |
| MediaToolbox | Set `StartRecorderServer = false` in the D22/D221/Default configurations | `tools/sweet-root-tweaks.py:117-122` covers every immediate `*/SubServerConfiguration.plist` variant | Covered |

## Lower-risk gaps

- `containers()` only sets owner/mode when it creates a missing directory.  It
  does not normalize an existing directory that has the wrong owner or mode.
- Audio and MediaToolbox changes are best effort: a missing plugin or a changed
  framework layout produces no warning and no failed build.
- `sweet-root-tweaks.py:10` still says it produced images v8-v14.  After the
  SystemConfiguration delta is implemented, the tool and README should describe
  v15 explicitly.
- `README.md:89` mentions Setup, activation, baseband removal, watchdogs, and
  media workarounds, but does not mention the v15 USB-Ethernet preference.

## Recommended minimum fixes

1. Add an idempotent `SystemConfiguration/preferences.plist` generator to
   `sweet-root-tweaks.py`, with path/owner/mode and schema validation, and add
   it to the rendered-root verification manifest.
2. Make missing mobileactivationd containers, expected audio files, and
   MediaToolbox configurations fail the build by default.
3. Split `mkiosroot.sh` into populate-nonjournaled and macOS-finalize steps;
   remove the documented journaled loop-mount assumption.
4. Do not use apfs-fuse `-l` as a successful data path.  Add a strict LZBITMAP
   reader or native macOS source-read step, plus a size/content manifest check.
5. Update the tool docstring and README to say that the reproducible root is
   v15 and list all post-population mutations.

## Bottom line

The committed tools implement nearly all of the v13/v14 root-image work, but
they do not implement the v15 SystemConfiguration delta.  Before the root build
is considered reproducible, the journaled-loop and LZBITMAP assumptions in
`mkiosroot.sh` must also be replaced; otherwise the builder can fail early or,
worse, claim success with incomplete file contents.
